# 工程约束

本文件维护对整套系统生效的工程限制，并明确区分已经确认的规则与待讨论建议。已确认规则同步到仓库根目录 AGENTS.md，供后续设计和实现持续执行。

## ENG-001 只保留当前正确方案

状态：已确认。2026-10-16，用户明确要求永远不写兼容性代码，只保留正确的最终方案。

“当前正确方案”指当前已经确认的设计；发现它有问题时可以替换，但替换应完成相关链路的整体更新，不能用保留旧分支掩盖尚未完成的改造。

### 实现规则

1. 删除失效实现。重命名、改接口、改模型或重构时，同步替换所有受影响调用，不保留 deprecated wrapper、旧导出或只为旧行为服务的工具函数。
2. 每个协议、配置及数据类型只有一套当前运行契约，不接受旧字段别名、不推断旧结构、不静默填值或把新格式失败转交旧解析器。
3. 不写为旧格式服务的双读、双写、新旧存储并行查询，也不设置切换旧实现的开关。
4. 不以支持未知旧客户端、旧 Jenkins 版本或旧配置为目标增加分支。需要支持的外部系统版本应明确选定并做契约验证。
5. 前端、CMDB、Pipeline、Runner 和接口客户端协同更新。发布步骤可以安排升级窗口，不以长期在线多协议作为默认方案。
6. 输入不符合当前契约时明确报错。错误信息说明字段或版本不被支持，不自动猜测用户意图。
7. 删除只验证已废弃行为的测试；测试当前行为、明确拒绝旧输入及迁移后的数据，不为保留测试而恢复旧实现。

### 数据与业务历史的边界

| 情况 | 处理原则 |
|---|---|
| 数据库字段或持久化格式发生变化 | 使用显式的一次性迁移并验证结果，完成后正常路径只处理当前结构 |
| 旧格式 Pipeline 定义 | 通过独立迁移转换，或明确拒绝；不在执行器中分派到旧解释器 |
| 已完成 Run、日志、审计和快照 | 按业务保留要求保存，不因不做兼容而删除或改写原始事实 |
| Job 模板版本与 PipelineRevision | 它们是业务版本记录；是否可继续使用在对应需求确认，使用时仍必须满足当前平台契约 |
| 历史快照重新运行 | 不自动选择旧引擎；必须先满足当前契约及当前执行准入条件 |
| 升级时存在活动 Run | 在发布与执行需求中设计升级窗口及收敛步骤，不擅自杀掉、重启或切换旧引擎 |
| 迁移失败 | 停止该次升级并报告原因，不自动双读旧结构或恢复旧业务逻辑 |

迁移文件属于升级工具，可以保留在版本化迁移目录；它们不在每次查询、参数解析或 Job 执行时承担历史格式转换。迁移和历史快照保存的具体方式仍在 OPS-06 与 DATA-02 讨论，本规则不授权清空数据库或删除用户数据。

正常重试、幂等、Jenkins 状态核对、事务回滚、取消收敛、备份恢复和业务上的重新部署不属于历史兼容。它们必须按当前契约执行，不能借机切回旧协议或旧逻辑。

### 文档规则

讨论中可以列候选方案。结论确认后，当前方案进入正文；未采用方案只保留必要的一两句决策原因，不再并列作为可选实施路线。历史变更记录可以保留，但必须明确它不是当前方案。

### 变更验收

- 实现、调用方、Schema、示例、配置、测试及文档表达同一套当前契约。
- 没有为了旧行为添加的别名、旧入口、回退解析、双读双写或实现切换开关。
- 如涉及存量数据，有显式迁移步骤、验证结果及历史记录保留安排。
- 不支持的旧输入明确失败，不静默得到另一套行为。
- 没有残留失效实现、废弃导出或只为旧路径服务的测试。

## ENG-003 简单可读按需抽象

状态：原则已确认。2026-10-16，用户澄清架构首先指代码风格、可读性和可维护性，要求不要复杂。

以普通函数、结构体和清楚的业务文件解决当前问题；出现真实重复、测试隔离或替换需要再提取接口和公共代码。不强制多层目录、public 契约、UnitOfWork、TxStores 或按操作逐个拆接口。具体风格规范见 ARCH-01，仍按实际代码需求评审，不反过来为模式制造需求。
