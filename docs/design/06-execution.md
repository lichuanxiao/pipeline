# 流水线执行与恢复规则

覆盖 RUN-01 至 RUN-09。执行以 MySQL 持久化状态为准，浏览器、HTTP 请求或某个 Worker 退出不代表运行停止。API 接收意图，Worker 负责推进、提交、观测和取消，二者复用业务代码。

## RUN-01 创建运行与准备

“运行”面板先展示应用、已发布修订、环境与保护标签，再填写代码引用、运行参数、可选发布计划和原因。默认当前发布修订与应用默认分支，明确提示“分支在取得执行槽后解析；需要固定版本请使用 commit”。选择历史镜像的部署专用流程自动锁定其来源 commit，不允许手工填写不一致代码。

提交前预检当前权限、流水线启用状态、应用环境、模板准入、参数、CMDB 上下文和凭据引用。网络读取在事务外；本地事务写 Run、StageRun、JobRun、配置/模板/上下文快照、事件与调度任务，返回202和详情地址。创建失败不留下半个 Run；幂等键处理浏览器重发。

Run 初始 QUEUED，取得 `(space, application, environment)` 槽后进入 PREPARING。内部源码准备执行将 requestedRef 解析为 commit 并验证能检出，所有源码 Job 都使用该 commit。完整 SHA 同样验证存在；无源码 Job 的部署专用运行使用所选镜像生产记录的 commit，不额外解析分支。准备不是用户 Stage，单独显示“准备运行”。

Release 运行强制使用计划环境与 plannedCommitSha；配置和计划在创建时固定，READY 计划不再可变。关闭/取消计划只阻止新建关联运行，已有 Run 继续。Run 快照不保存密钥值，当前授权、环境硬停用与凭据撤销仍在后续执行准入复核。

**验收：** 同键请求只建一个 Run；排队中分支移动最终明确显示实际 commit；历史镜像部署不伪造来源；CMDB503不留下缺快照记录。

## RUN-02 状态机与 Stage 屏障

| 对象 | 非终态 | 终态 |
|---|---|---|
| Run | QUEUED、PREPARING、RUNNING、WAITING_MANUAL、FAILING、CANCELING | SUCCEEDED、FAILED、CANCELED、TIMED_OUT |
| Stage | PENDING、RUNNING、WAITING_MANUAL、FAILING、CANCELING | SUCCEEDED、FAILED、CANCELED、TIMED_OUT、SKIPPED |
| Job | PENDING、WAITING_MANUAL、READY、DISPATCHING、QUEUED、RUNNING、CANCELING | SUCCEEDED、FAILED、CANCELED、TIMED_OUT、SKIPPED |

Job 主路径为 PENDING → READY（自动）或 WAITING_MANUAL → READY（人工）→ DISPATCHING → QUEUED/RUNNING → SUCCEEDED。Runner 可能先认领再收到提交响应，因此 DISPATCHING 可直接到 RUNNING。未启动任务可直接取消/跳过，状态变化始终校验当前状态，不允许终态回退。

一次 Run 仅一个业务 Stage 活动。激活时所有自动 Job 具备执行资格，所有手动 Job 独立等待；资源不足只是排队，不改变并行语义。存在 READY/提交/排队/运行 Job 时 Stage 为 RUNNING，另返回 manualWaitingCount；只剩人工等待时 WAITING_MANUAL；全部成功才结束 Stage 并激活下一 Stage。

多个 Job 同时结束，以 Run 行锁串行聚合。状态变化、待办任务与事件同事务写入。失败/取消优先阻止推进；后续 Stage 标记 SKIPPED 或取消原因，不能把“未执行”画成成功。无空 Stage 或零 Job 的发布定义。

syncState=OK/STALE/UNKNOWN 与生命周期分开。网络异常保留最后已知状态并显示最后核对时间；Run 在存在未知远端状态时不能宣告成功或释放互斥槽。

**验收：** 两 Job 同时成功只激活一次下阶段；自动任务不会等待手动兄弟；全部成功后才算成功；未知状态无法推进。

## RUN-03 单个手动 Job 放行

只有当前 Stage、WAITING_MANUAL、Run 仍可继续、模板与环境未禁用且用户有当前环境执行权限时可触发。运行页每个等待 Job 有“执行此任务”，确认面板显示真实 commit、输入来源、镜像 digest、目标和超时；protected 环境要求原因。

允许在自动兄弟运行时放行手动 Job；同 Stage 不存在输出依赖。没有“一键放行整个 Stage”，避免误触发多个不同副作用。输入在进入可执行状态时从固定来源解析并写入一次，手动按钮不能改参数/镜像/目标；要改则复制参数创建新 Run。

事务锁 Run 再锁 Job，复核资格，WAITING_MANUAL→READY，记录 triggerUserId、triggeredAt、reason，创建推进任务。相同幂等键返回原结果；另一个请求在已放行后409 JOB_NOT_WAITING，并返回当前状态便于刷新。与取消/失败竞争按同一 Run 锁决定，任何晚到放行不能恢复资格。

事务内同时用数据库当前时间检查人工截止，即使超时Worker尚未来得及改状态，已过deadline也拒绝放行；Runner认领同样检查首次排队截止与撤销标记。

普通 CMDB 修改不改变旧快照；确认面板提示“应用配置已更新，本次使用运行时快照”。空间/目标/凭据硬停用阻止放行或后续认领，要求新运行或管理员恢复资格，不静默换目标。

**验收：** 两人同时点击只放行一次；权限刚被撤销返回403；放行一个手动任务不影响另一个；取消先提交时无法执行。

## RUN-04 队列与并发

| 约束 | 推荐默认 | 占用与释放 |
|---|---|---|
| 应用+环境活动 Run | 1，所有 Pipeline 共享 | PREPARING 起占用，Run 确认终态释放 |
| 平台活动 Run | 100 | 取应用槽时占用；等待手动继续占用 |
| 空间活动 Run | 20 | 同上 |
| 平台执行中 Job | 100 | 包含源码准备、模板测试和只读诊断，在途与未知执行均占用 |
| 单 Run 执行中 Job | 4 | DISPATCHING/QUEUED/RUNNING/CANCELING 占用 |
| 空间执行中 Job | 10 | 同上；未知远端状态继续占用 |
| Controller/节点池 | 以管理员配置容量为上限 | 与平台和空间限制同时生效 |
| 待运行数量 | 空间1,000、单 Pipeline100 | 超限创建返回429及当前队列入口 |

这些是可配置部署基线，首期暂不做按业务用户自由配置的优先级。调度按空间轮转、空间内 FIFO；被同应用槽阻塞的 Run 可跳过，让其他应用前进。已等待项有等待时长可见，不允许新同槽 Run 插队。

Job 达到执行资格不等于已经占 Executor。平台在提交前取得执行配额，Jenkins 可再因 Agent/Executor 等待；一个 executionId 只占一次逻辑配额，重复 Jenkins 构建记录单独计数并清理。源码准备和模板测试也计入配额。

人工等待继续占应用环境槽，这是首期保守的交付顺序规则。详情与列表显示“等待人工，正在阻塞后续N次运行”，可跳转或取消；不提供强制释放活动锁按钮。

**验收：** 同应用环境不同流水线不同时部署；其他空间有公平机会；双 Worker 不超配；等待原因可区分平台限额、应用互斥和 Jenkins 资源不足。

## RUN-05 失败、部分结果与外部副作用

Job 失败包括脚本非零、Jenkins FAILURE/UNSTABLE、准备失败、输出缺失/非法、来源不符和执行准入拒绝。首个失败使 Stage/Run 进入 FAILING，停止新增工作；未提交自动任务与未放行手动任务 SKIPPED；已提交未认领执行撤销资格并取消队列；已认领兄弟继续收敛，保留完整结果。

失败与认领同锁竞争：认领先完成视为已启动；失败先完成则拒绝认领。全部在途任务已知终结后 Run FAILED；若是超时导致整体停止则最终 TIMED_OUT。不能只因主任务失败就释放仍有远端副作用的运行槽。

成功定义为 canonical Jenkins SUCCESS 且输出契约通过。失败保留 errorCode、阶段、必要诊断、日志链接及实际已产生的镜像/部署事实。部署更新已生效但后置检查失败时，不声称“未部署”，也不自动回滚。

**验收：** 失败后新手动按钮禁用并说明；运行中的兄弟结果仍收集；UNSTABLE 不成功；输出失败阻止后续 Stage。

## RUN-06 取消与终止

任一有对应环境权限的成员可以取消非终态 Run，填写原因，确认框列出运行/排队/等待任务并说明外部变更可能已经发生。请求返回202和取消操作，不等待 Jenkins HTTP 收敛。

事务写 cancelRequestedAt、actor、reason，将 Run 置 CANCELING，撤销未认领资格，生成取消任务。尚未提交的 Job 直接 CANCELED；队列请求取消，canonical build 请求停止并继续轮询。取消与成功竞争：Run 已终态则409；取消先提交则不进入后续 Stage，Job 仍记录实际观测到的成功/失败，Run 最终 CANCELED。

Jenkins 不可达时保持“取消中 · 状态核对中”，仍占槽。运维只能在确认 Agent 已隔离、构建已停止或执行资格已撤销后，录入证据做人工收敛；操作保留双重事实“人工确认终止”和最后远端观测，不伪装成 Jenkins 自动成功结果。

首期不提供“忽略远端、立即释放锁”；网络故障不能成为下一次部署与旧脚本并发的理由。

“远端结束”的证据包含Jenkins构建不再building，并且受控前台进程已终止；Agent失联时应确认Pod删除/节点隔离或静态Agent进程树终止。workspace清理失败可以隔离目录后收敛，但不能把无法确认脚本停止当作普通清理失败绕过锁。

**验收：** 取消接口重试不重复改结果；失联不显示已取消；迟到 Runner 不能绕过已撤销资格；关闭网页不取消 Run。

## RUN-07 超时

| 阶段 | 默认起点与时限 | 处理 |
|---|---|---|
| 等待应用槽/平台容量 | 创建后24小时 | 未提交任务直接超时终结 |
| 源码准备 | 认领后20分钟 | 请求停止并核对 |
| 人工等待 | 该 Job 进入等待后24小时 | 超时取消该 Run 并停止其他在途任务 |
| Jenkins 排队/等待认领 | 首次提交后30分钟 | 撤销认领资格、取消全部相关队列项 |
| Job 执行 | canonical claim 起；测试15、构建30、部署15分钟 | 包含 Agent 分配、检出和脚本；请求停止 |
| 清理 | 独立60秒 | 标记清理失败并隔离目录/Agent，不无限占收尾流程 |

模板声明默认和最大执行超时，节点只能在允许范围内覆盖；人工等待时限由空间管理员设置，首期不默认无限等待。运行页显示截止时间与剩余时间，等待30分钟后出现在站内待办的超时提醒，无外部通知发送。

Run 不另设与人工等待冲突的全局总时限。超时是停止意图，已认领任务未确认终止时保持 CANCELING/UNKNOWN；最终 TIMED_OUT 只在远端收敛或确定不能执行后产生。

**验收：** Worker 重启不重置计时；调度重试不延后首次排队截止；超时与人工点击按当前状态决定；清理失败不会报告资源已经干净。

## RUN-08 持久化、租约与故障恢复

同数据库保存 scheduler_tasks：kind、aggregateId、taskKey、nextRunAt、leaseOwner、leaseUntil、leaseFence、attemptCount。短事务 SKIP LOCKED 领取到期任务，提交后做网络操作；任务租约30秒，每10秒续租，调度唤醒1秒、构建轮询3秒加抖动，错误退避2–60秒。所有写回检查 fence 和对象状态，失去租约的旧 Worker 不能覆盖结果。

executionId标识一次逻辑执行，业务ownerKind为SOURCE_PREPARATION/JOB_RUN，受控只读诊断使用DIAGNOSTIC_OPERATION；一个owner只对应一个逻辑execution，允许多次提交记录。Runner在运行脚本前认领唯一canonical build，重复build提前退出。数据库唯一约束、认领和状态条件共同保护，租约本身不能保证远端只执行一次。

提交超时先按 executionId 查队列/构建与 claim；未认领且未找到时可重提同一 ID。已认领构建失联不自动开启替代脚本。恢复扫描非终态 Run、过期租约和陈旧观测，继续推进/核对；人工等待原样保留，已解析 commit 不重新解析。

Runner 的唯一认领限定平台重复提交，不宣称所有外部副作用 exactly-once。构建/部署模板应使用固定目标、digest、幂等更新和可查询结果。后台系统有“异常执行”页列出未知状态、最后观测、重试次数与人工核对动作。

**验收：** 杀 Worker 后另实例恢复；旧 fence 写回被拒；提交响应丢失不重复跑业务脚本；API 重启与页面断线不影响已接受任务。

## RUN-09 重新运行与修复

首期提供“重新运行”，始终新建 Run；对话框预填原修订、固定 commit、参数与环境，重新读取当前 CMDB 上下文和准入。显示与原目标的差异并要求确认，不能声称完全复刻原运行。原模板/修订不满足当前契约时要求修复发布，不启动旧解释器。

不提供原 Run 内单 Job 重试、失败点恢复或脚本自动重试；这些会引入旧产物、部分副作用和执行身份歧义。网络读取/提交核对可以自动重试，但不能把业务脚本重新执行当作网络重试。

修复部署可创建“部署指定镜像”新 Run，选择本应用已有产物，显示来源 commit、生产记录、目标及当前镜像。回滚是把历史 digest 作为一次新的部署运行，保留原因和新记录；不改写原部署历史、不自动切旧代码路径。

**验收：** 新旧 Run 有 lineage/reRunOfId；旧失败记录不被覆盖；重新运行提示当前目标差异；部署历史镜像验证来源且生成新的部署事实。
