# 流水线配置与组装交互

覆盖 CFG-01 至 CFG-08。编辑器的主要任务是把市场能力按顺序组织成可运行定义，随时保存未完成内容，并在发布前准确指出问题。

## CFG-01 草稿 CRUD

每条 Pipeline 一个共享草稿，包含 schemaVersion、parametersSchema、parameterDefaults、stages 和 draftVersion；元数据与草稿分别编辑。草稿允许缺少参数、空 Stage、失效引用等未完成内容，但必须满足基础类型、大小限制和可识别节点结构，不接收任意 JSON 垃圾。

进入页面读取草稿与 ETag；首次创建有空草稿。编辑后1秒防抖自动保存，任一时刻至多一个保存请求；后续变化排队携带上次成功 ETag，避免覆盖。页面显示“未保存/保存中/已保存于xx/保存失败”。另有立即保存按钮，不把“已保存”写成“已发布”。

草稿持久化后编辑器再发布，运行始终使用发布修订。“重置为某修订”需确认会替换当前草稿，保留选择修订的来源；“清空草稿”只清配置，不删除 Pipeline 或历史。用户离开未保存页面时提示，可下载配置，不向浏览器磁盘自动存敏感上下文。

**验收：** 不完整草稿能保存但不能发布；请求乱序不丢输入；保存失败仍保留本地编辑；重置不改变现有默认修订。

## CFG-02 Stage 增删改与排序

桌面采用纵向 Stage 卡片，顺序标号和清楚的串行连接；Stage 内 Job 并列/换行展示，避免横向无限画布。新 Stage 默认在当前后方创建，名称必填，key 自动生成且可在高级区修改。key 在定义内唯一，不用数组下标作为身份。

支持新增、改名、复制、删除、拖动排序以及“上移/下移”键盘等价动作。空 Stage 在草稿显示“添加任务”，发布时拒绝。删除 Stage 展示其中 Job 数和被其他 Stage 引用的输出，确认后保留下游失效绑定供用户修复，不默默改成固定值。

复制生成新的 Stage/Job key，保留正常上游引用；不会自动把原下游消费者改接副本。排序后立即重新校验前序依赖，突出受影响节点。改 key 是一次本地原子编辑，同时更新明确的内部引用，再统一保存，不保留旧 key 别名。

限制：最多20 Stage，每 Stage 最多20 Job，全定义最多100 Job；错误告知实际数量。顺序用数组保存，服务端发布时再验证。

**验收：** 用键盘可调整顺序；删除前看得到影响；移动导致非法依赖时禁止发布；节点 key 不因重排改变。

## CFG-03 Job 节点增删改

Stage 内“添加任务”打开市场抽屉，显示类别、搜索与当前可用版本。选择后立即创建节点并打开右侧配置区，显示名称、模板版本、自动/手动、超时和输入。默认自动；示例中的部署默认手动，用户可按权限和策略显式设置为自动，protected 环境仍按运行角色准入。

节点支持复制、移除、重命名和同 Stage 排序；同 Stage 排序只是显示顺序，不产生执行依赖。移动到其他 Stage 用“移动到”选择器并显示引用影响。单个 Job 的输入配置失败不阻止其他节点编辑。

升级模板显示旧/新版本、字段变化和受影响下游输出，显式确认后重新校验。版本不可用时节点保留便于修复；不自动换成最新版。复制节点生成新 key，只复制配置，不复制执行结果。移除被引用节点必须确认，失效引用就地可见。

**验收：** 同 Stage 多任务标注并行；手动只设置该节点；更换版本不清空仍合法的同名同类型参数；没有静默字段映射。

## CFG-04 参数与数据绑定

| 来源 | 用户交互 | 固定时点 |
|---|---|---|
| literal 固定值 | 按类型输入、枚举或列表 | 发布修订时固定 |
| run 运行参数 | 选择已声明参数；定义默认值/帮助 | 创建 Run 时固定 |
| cmdb 应用交付字段 | 从允许字段树选择，显示类型与示例 | 创建 Run 读取上下文快照 |
| job 上游输出 | 选择前序 Stage 的 Job 与输出 | 生产 Job 成功后解析并固定 |

同 Stage 不允许互相读取输出，因为它们并行且无先后保证；选择器仅列出前序 Stage，手工导入也同样校验。不支持任意 JavaScript、模板表达式或拼接命令；需要组合值时由能力显式接受多个参数完成。

运行参数支持基础类型/枚举/默认值/必填/帮助；没有 secret 类型。CMDB 路径为白名单：应用 key、源码 commit/仓库、镜像仓库、环境 key 等非敏感字段。目标与凭据由系统上下文提供，不能让普通输入覆盖。引用记录来源而非复制一次显示值，避免误以为预览值已经是实际运行值。

镜像输入使用语义化选择器，默认绑定上游构建产物；部署专用流水线可选同应用历史镜像，创建 Run 时同时采用其 commit。值类型必须一致，integer 可传 number；枚举和格式在真实值解析后再校验。

**验收：** 同 Stage 引用不能发布；删除上游输出有明确定位；参数中 null 与未设置区分；部署输入无法改写凭据。

## CFG-05 校验与执行计划

自动执行轻量本地校验；后端提供完整校验，点击“校验并发布”使用当前已保存草稿 ETag，不信任前端结果。检查结构、唯一 key、可用模板版本、必填和未知输入、类型、前序关系、超时、环境可表达性、空间权限和部署冲突。

同 Stage 最多一个 DEPLOYMENT Job，首期不支持同 Run 多目标；源码能力要求应用存在源码配置。发布验证契约可表达性，具体环境连接、凭据当前有效性在新 Run 预检。警告如模板弃用不能被普通“忽略”变成可发布。

校验响应分 errors/warnings，每项含 code、fieldPath、stageKey、jobKey、input 和建议。错误面板显示总数，点击滚动并聚焦字段；不能只 toast 一句“配置错误”。预览计划列出顺序、并行组、人工等待点、来源绑定和节点池能力，明确不是一次真实执行。

ExecutionPlan 保存解析后的固定模板引用、依赖关系、超时与需求，Definition 保留编辑结构；二者同一修订存储，planVersion 表示当前编译契约。首期不生成整条流水线 Jenkinsfile。

**验收：** 前端跳过校验仍被服务端拒绝；并行冲突与错误引用能定位；两 Job 同时结束不会依赖定义重新编译来推进。

## CFG-06 发布、差异与配置回退

发布对话框显示变化摘要、目标环境范围和手动点，要求简短变更说明。后端在事务外编译指定草稿，再锁 Pipeline 并复核 ETag/模板准入，事务内创建 revisionNo 递增修订与审计并更新默认修订；草稿并发改变则412，不发布另一份内容。

修订保存 definition、executionPlan、编译契约版本、模板内容摘要、创建者和说明，不允许修改。发布使用幂等键；重复点击不创建两个版本。发布后编辑草稿不影响历史/活动 Run。

修订列表可按 Stage/Job/参数比较，也可查看格式化 JSON。配置回退是“将历史修订复制到草稿 → 校验 → 发布新修订”，保留当前平台契约；不是把默认指针偷偷拨回旧引擎。历史模板被封禁时必须修复后才能重发。

**验收：** 发布与保存竞态不会产生未审阅版本；回退生成新编号；发布本身不启动 Run；历史修订内容不变。

## CFG-07 定义格式、导入导出与迁移

当前唯一格式 schemaVersion=devops.pipeline/v1，示例与结构契约见 [定义示例](../examples/pipeline.definition.v1.json) 和 [Schema](../schemas/pipeline.definition.v1.schema.json)。公开 API 字段使用 camelCase，模板自定义输入 key 可以使用 snake_case，含义由其 Schema 确定。

导出只包含定义、模板 key/版本和普通默认值，不含会话、密钥、运行输出、Jenkins 地址或执行凭据。导入最大1 MiB，先解析和展示差异，确认后替换草稿；环境归属与应用目标重新绑定，绝不直接导入为发布修订或运行。

未知 schemaVersion、未知字段、非法 Schema 拒绝并指出原因；未填写完成的内容可按草稿规则导入。平台格式升级用离线显式迁移，重新编译/发布后才可新运行；历史原文保留用于审计展示，当前执行器只理解一套格式。

**验收：** 导出再导入当前格式保留含义；旧格式不会自动走旧解析器；导入失败不破坏原草稿；引用不适用时能保存待修复。

## CFG-08 多人编辑与断线保护

单共享草稿使用 ETag 乐观锁，首期不做实时协同光标或自动结构合并。412 时立即停止自动保存，显示“草稿已被他人更新”，保留本地版本、服务端版本与修改时间；提供查看差异、下载本地、加载服务端和复制为新流水线。明确确认后才能把本地内容作为基于新 ETag 的替换保存，不静默覆盖他人内容。

本地撤销/重做保存最近20次结构编辑，作用于当前编辑会话；自动保存后的撤销形成新草稿版本，不能撤销他人保存。网络恢复后先读取最新 ETag，再判断是否安全重发。

选中节点和筛选放在 URL，字段焦点不因后台保存丢失。离开/切空间有未保存内容时提示；不在本地持久化含应用上下文的完整运行参数，用户可主动下载普通定义。多人编辑提示作为辅助，最终仍以服务器版本检查保证正确。

**验收：** 两人修改第二人收到冲突且输入保留；同浏览器两标签页同样受保护；断网时不显示“已保存”；冲突处理可完全用键盘完成。
