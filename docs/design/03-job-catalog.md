# Job 市场功能与契约

覆盖 JOB-01 至 JOB-08。市场面向流水线编辑者展示可选择的原子能力，模板脚本由平台管理员管理。业务用户看到参数、输入输出、用途和限制，无需了解 Jenkinsfile。

## JOB-01 原子能力与对象边界

JobTemplate 是能力身份，如 image.build-push；JobTemplateVersion 是一份已发布契约与脚本；Definition 中的 Job 节点是对某版本的一次配置；JobRun 是该节点的一次实际执行。界面分别称“能力”“能力版本”“任务”“任务执行”，详情显示技术 key 供诊断。

一个能力完成一件具有独立成功判据的事，例如测试、构建推送镜像、部署；不把整条流水线包装成一个模板。需要共享同一工作目录才能完成的内部步骤可以在一个 Job 内完成，例如 build+push。首期一个 Job 对应一次 Jenkins 原子执行，不把平台 Stage 映射成 Jenkins input 等待。

分类 quality、build、deploy，效果类型 READ_ONLY、BUILD、DEPLOYMENT 用于策略校验和追溯，不作为脚本权限沙箱。普通用户不能提交 Groovy、命令字符串或任意 Jenkins Job 名。

**验收：** 同模板可多次添加并分别配置；修改一个节点不会修改市场版本；平台能够识别部署能力并限制目标冲突。

## JOB-02 输入输出与表单

版本定义 inputsSchema、outputsSchema，使用 JSON Schema 2020-12 的受控子集。首期支持 object、array、string、integer、number、boolean、enum、required、长度/数值上下限、pattern、description；array 最多100项、嵌套最多4层。禁用外部 $ref、动态表达式、oneOf/anyOf 等暂不支持的模板表单关键字，发布时即拒绝，不能前端无法编辑而后端允许。[规范来源](https://json-schema.org/draft/2020-12/json-schema-validation)

额外提供字段标题、帮助、顺序、敏感用途说明和语义类型，例如 container_image，辅助绑定选择。语义类型不替代实际值校验。默认值在添加节点时显式填入并保存，不依赖 Schema 校验器自动补值。

输出必须是结构化 JSON 对象，最大64 KiB；成功时验证后只写入一次。镜像输出声明 image_ref 与 image_digest，来源关联生产 JobRun。大文件使用制品 URI 和校验和；首期直接跨任务传递的产物为镜像，不复用上游工作目录。

表单每个输入可选固定值、运行参数、CMDB 字段或前序 Stage 的 Job 输出。必填、类型、来源和帮助就近显示，错误定位到字段；缺输出视为 Job 失败，不默认空串。

**验收：** 新增未知输入被拒绝；整数可绑定 number，其他隐式类型转换不允许；Schema 通过但镜像来源不合法仍会失败；输出超限有明确错误。

## JOB-03 脚本与执行环境

版本保存脚本解释器 bash、脚本文本、需要源码标记、节点池能力、工具镜像/清单、默认与最大超时、执行协议版本和脚本摘要。管理员在能力编辑页编辑，发布后文本不可改；首期不远端下载“最新脚本”。

Runner 可信代码固定，先准备目录、校验输入、绑定最小凭据、按 commit 检出源码，再调用脚本。输入以 DEVOPS_INPUT_FILE 提供，输出写 DEVOPS_OUTPUT_FILE；不把用户值拼进 Groovy、不 eval 输入。脚本根目录由 Runner 设置，路径规范化及真实路径检查须在源码检出后再次进行。

构建与部署使用不同节点池。构建池可执行应用仓库内受信任范围的测试脚本，但不带部署凭据；部署模板不执行仓库内自定义脚本。平台控制工具集合和镜像 digest，模板只选已登记能力，不允许业务用户任意指定 Agent 标签或特权挂载。

**验收：** 参数中的引号、换行作为数据传递；源码路径逃逸被拒绝；构建容器读不到部署凭据和 Runner 控制面身份。

## JOB-04 凭据与上下文

模板声明命名 credentialSlots，每槽指定 kind、用途、contextPath；例如 registry 从 image.credential_ref 取得。sourceRequired 启用平台固定 source 槽；应用代码不能覆盖集群、镜像仓库和凭据 ID。普通参数与 outputs 禁止承载密钥。

空间管理员在 CMDB 登记凭据引用，实际密钥保存在 Jenkins Folder 凭据中；平台管理员通过 Jenkins 管理流程配置和轮换。浏览器只看到名称、类型、用途、引用状态。模板调试也只选择测试空间获授权的引用。

Runner 控制 API 的凭据仅在可信控制步骤使用，不传给执行仓库脚本的 Agent；源码凭据只在检出时绑定，registry 只在镜像推送段，deploy 只在部署段使用。文件权限限制到任务用户，结束清理。Jenkins 掩码减少意外输出，不能防止能访问凭据的脚本主动泄漏，隔离以代码信任与最小权限为基础。[Jenkins 说明](https://www.jenkins.io/doc/book/security/securing-org-folders-and-multibranch-pipelines/)

**验收：** 越空间引用、用途不符、撤销凭据均阻止执行；运行快照与日志 API 不返回密钥；调试模式不能绕过空间授权。

## JOB-05 版本生命周期

模板身份可有 DRAFT、PUBLISHED、DEPRECATED 版本。版本号由管理员填写稳定的major.minor.patch，遵守SemVer核心数字规则，首期不接受预发布与构建元数据后缀；templateId+version唯一。发布后内容、Schema、脚本摘要不可变，身份的名称说明可改，历史引用显示所用版本标签。

PUBLISHED 可添加、发布和新运行；DEPRECATED 不用于新添加或新发布，已发布流水线可继续启动并提示“建议升级”。另有 blocked 标志用于安全封禁：禁止新 Run 与尚未认领的执行，已有 Jenkins 任务由管理员选择取消；它不是历史兼容分支。草稿里的弃用引用可保存但不能发布。

升级版本由用户显式选择，显示参数与输出差异。只保留新契约中名称和类型都匹配的配置，删除/重命名的字段放在差异提示中要求重配，不能悄悄猜映射；下游绑定重新校验。新节点默认最新可用稳定版本，已保存节点不自动升级。

**验收：** 发布版本不可编辑；弃用不破坏历史查看；封禁任务不能被队列重提绕过；改版后有失效字段提示而非旧别名。

## JOB-06 测试与发布

平台管理员从模板草稿进入“测试运行”，选择测试空间、应用、普通环境和测试参数。测试使用独立 CatalogTestRun，保存候选脚本摘要和结果，执行受相同队列、配额、日志和认领约束；必须占用该应用环境执行槽，不因调试而绕过部署互斥。

只读或构建能力可在专用测试应用验证；部署能力测试必须在测试目标，protected 环境拒绝。发布要求契约校验通过、候选内容摘要与最近成功测试一致、描述/示例/工具/凭据说明齐全。修改脚本或契约后原测试变为过期。

测试页显示阶段为“准备、执行、输出校验”，可取消、查看输入摘要和脱敏日志。测试失败保持草稿，不生成可用版本；已发布版本有问题时封禁并发布修正版，不能修改原脚本。版本回退是显式选择另一个当前可用业务版本，不切换旧协议引擎。

**验收：** 修改草稿后不能沿用旧测试发布；测试部署不会进入生产；测试取消失联时仍保留槽位与核对状态。

## JOB-07 市场检索与使用

可见范围 GLOBAL 或指定空间列表，由平台管理员维护；普通用户只见有权能力。卡片显示名称、分类、说明、推荐版本、效果标签、输入数、是否需要源码；搜索支持名称/key/描述，筛选分类与状态。空市场给管理员“发布首个能力”，普通用户看到联系空间管理员的说明。

详情页先展示用途、输入输出与示例，再展示版本变更和使用中的流水线数量。用户从编辑器打开市场抽屉，选择能力版本后回到当前 Stage 并自动打开配置，不跳转丢失草稿。列表不能一键执行模板，执行应有明确应用、环境与上下文。

移除可见范围影响新选择与新 Run，历史快照仍按所属空间可读。跨空间不能通过模板 ID 猜到私有脚本。权限撤销后的草稿保留节点名称但提示不可用，发布和执行拒绝。

**验收：** 市场筛选不会丢当前编辑上下文；选择后有明确新节点反馈；用户不能读未授权模板或测试记录。

## JOB-08 首批能力与成功判据

| 能力 | 普通输入 | 系统提供 | 必需输出与成功判据 |
|---|---|---|---|
| source.test | script_path，相对路径 | 仓库、固定 commit、测试池 | 脚本退出0，outputs={}；输出协议仍需合法 |
| image.build-push | dockerfile、context | 固定源码、目标镜像仓库、推送凭据、构建池 | 推送成功；image_ref 为 repository@sha256，digest 对应且仓库正确 |
| kubernetes.deploy | image_ref、release_note | 固定集群/Namespace/Deployment/容器、凭据、部署池 | 请求更新并 rollout 成功；输出镜像、目标、rollout_succeeded=true |

测试可添加两次，分别执行 .devops/test.sh 与 .devops/lint.sh。部署前校验镜像生产记录属于当前空间应用与已解析 commit；允许部署专用流水线选择历史镜像，但须同步采用该镜像来源 commit。首期不接受未登记来源的任意外部镜像。

部署前读取当前镜像与 Deployment 标识，记录更新意图；成功后读取实际状态、generation、observedGeneration 和镜像。脚本失败后仍尝试保存可确认的外部变化，不能把退出码等同于“未发生部署”。不自动回滚；人工修复通过新的部署 Run 完成。

**验收：** Jenkins SUCCESS 但缺输出、digest 不一致、rollout 超时均不成功；同 tag 被覆盖不影响 digest 部署；后置验证失败仍能查看已发生的部署事实。
