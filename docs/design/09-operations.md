# 通用运行安全与交付运维

覆盖 OPS-01 至 OPS-07。用户能登录并持续使用系统，依赖故障时得到真实可操作的反馈，维护者有可验证的部署、升级、备份与恢复流程。

## OPS-01 登录与跨服务授权

本地账号由平台管理员创建，首次登录强制改密；无公开注册和邮件找回。密码12–128字符，允许长口令，不强制复杂字符拼图；登录失败提示不区分用户名是否存在，按账号/IP限速与临时冷却，管理员可审计解锁。密码使用 Argon2id、每用户随机盐，基线至少19 MiB/2次/并行1，实施时按服务器校准成本。[OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

CMDB identity 保存服务端会话，浏览器仅持 opaque Secure/HttpOnly/SameSite=Lax Cookie，空闲30分钟、绝对8小时过期；退出/改密/停用撤销相应会话。首次管理员用一次性引导密钥创建，成功后关闭引导入口，默认凭据不得写入仓库。

同源网关路由三服务。写请求核对 Origin 与绑定会话的 CSRF token，登录也校验来源；不允许宽泛跨域凭据。Pipeline 每次浏览器请求经内部 CMDB authorize 核对会话与空间动作，服务身份只获得必要授权结果；授权服务不可用时503，保留用户输入，不能用旧角色缓存放行。只读SSE每15秒复核，失效关闭。

已接受自动工作沿 Run 授权继续，不因创建者登出/移除自动停止；新的人工操作使用当前身份。环境硬停用、凭据撤销、模板封禁仍阻止后续执行准入。服务间与Runner使用独立最小范围身份、TLS和可轮换密钥，不复用用户Cookie。

**验收：** 登出后旧会话不能写；修改角色影响下一请求；CSRF/越空间访问拒绝；授权服务失联不返回假403或允许写入。

## OPS-02 密钥生命周期

部署连接密钥由Kubernetes Secret/部署Secret提供，应用库保存引用，不在Git或可下载配置中保存值。Jenkins Folder保存执行凭据，CMDB保存其元数据与用途，Worker只传受控引用；不建设第二套密钥明文仓库。

平台管理员登记、验证、轮换和撤销服务密钥；空间管理员绑定已授权引用。轮换先在测试空间验证，再更新引用版本或外部值，保留审计与最后验证时间；正在执行的构建按实际已绑定值完成，不声称被即时替换。撤销展示受影响流水线与活动执行，必要时显式取消。

只读API、日志、trace、panic、诊断包与备份均避免意外泄露；备份中不可避免含Jenkins加密密钥时单独加密与限制恢复权限。过期凭据报可操作错误，如“镜像推送凭据不可用，请管理员验证”，不显示token或原始认证头。

**验收：** 搜索日志/快照/前端包没有测试密钥；轮换后新执行生效；旧身份被撤销后不能claim；备份访问有审计。

## OPS-03 外部依赖故障

| 依赖故障 | 用户操作与后台行为 |
|---|---|
| CMDB/授权 | 新Run/新人工动作503；后台准入暂停并核对，不改旧快照 |
| Jenkins提交响应不明 | 显示核对中，查参数/claim，未认领时可重提同ID |
| Jenkins已认领后失联 | 不重跑脚本，保留槽与最后状态，退避核对 |
| Git不可用/ref不存在 | 准备失败，给出来源错误；不启动业务Stage |
| registry不可用/digest不存在 | 构建/部署失败，保留已发生事实，不改成tag降级 |
| K8s不可用/rollout失败 | 执行失败或超时，核对实际镜像，不自动回滚 |
| 对象存储不可用 | 执行状态可完成但日志标记归档异常，暂缓Jenkins清理 |
| MySQL不可用 | API503、Worker停止推进，远端继续；恢复后对账 |

网络重试有抖动、上限与超时，错误不能在热循环刷日志。读取可安全重试，非幂等副作用必须使用原操作身份核对；不做无理由换Controller、换集群、换旧协议。平台“异常执行”页按影响展示处理者、最后核对时间、建议动作与证据，不给危险的“一键标成功”。

**验收：** 注入每种依赖故障均能解释原因；恢复不重复执行已认领脚本；归档故障不返回空日志掩盖问题。

## OPS-04 可观测性

API日志关联 requestId、traceId、spaceId、actorId；Worker日志关联 taskId、fence、runId、jobRunId、executionId、controller/build。对用户返回必要requestId，详细堆栈只供运维。请求正文和凭据不作为默认日志。

指标包括API延迟/错误、数据库连接/锁等待、待办积压与年龄、租约过期、各层队列、人工等待、执行成功/失败、UNKNOWN数量与时长、Jenkins资源、日志采集延迟和清理失败。runId/commit等高基数字段不作为metrics标签，留在日志/trace。

建议告警：未知执行>5分钟、最老可调度任务>60秒、日志落后>60秒、数据库/授权持续故障、失败率突增和备份失败。阈值是初始运维策略，需负载调优。告警路由由部署环境配置；当前设计不授权向真实聊天或邮件发送消息。

**验收：** 从失败详情可关联到完整请求与远端build；指标能区分队列堵塞和脚本慢；查询不因高基数爆量。

## OPS-05 部署、退出与升级

生产建议同源网关、Next.js、CMDB API、Pipeline API、Pipeline Worker、MySQL双逻辑库、S3兼容对象存储和专用Jenkins；不强制Redis或消息队列。API可多副本，Worker以DB租约协调，CMDB/Pipeline数据库账号互不可访问。开发用Compose与模拟Jenkins，真实联调用隔离Jenkins/K8s。

镜像、依赖和配置全部固定版本/摘要；Go、Gin、Next.js、插件具体patch在实施准入清单锁定并通过契约测试。迁移为单独Job，成功后服务ready，多个副本不能各自竞争自动迁移。优雅退出只结束本地工作，不杀远端构建。

普通无契约变化发布可逐服务滚动，破坏性变化按工程章节维护窗口：停止新写/新运行，排空活动执行，备份，单次迁移，协调部署API/Worker/Runner/前端，验收后开放。浏览器版本不符提示保存普通草稿后刷新，不让旧页面默默提交旧字段。

程序回退仅在数据契约仍匹配时部署上个包；有破坏性迁移则按备份恢复计划执行，不通过双读双写维持两个运行协议。架构简单性不替代这些执行正确性要求。

**验收：** 停一API/Worker不丢任务；不兼容包不能ready；升级后模板测试、运行、手动与取消场景全部通过。

## OPS-06 数据迁移、备份与恢复

SQL迁移按服务版本化、带校验和，执行前备份并测试耗时/锁影响；迁移后验证关键行数、引用、状态和快照摘要。迁移失败停升级，不让正常路径解释旧结构。历史快照保留原文和当前可索引摘要，不能伪造当时内容。

推荐MySQL每日全备+binlog持续归档、对象存储版本化、Jenkins home/JCasC/插件/Secret受控备份。以RPO15分钟、RTO4小时为演练目标，尚非已实现SLA。初期两库同实例可使用一致时间点备份；分实例时记录共同检查点并恢复后核对跨服务引用。

恢复前冻结入口和Runner认领、停止/隔离可能仍运行的Agent，保留事故后新增的可取证日志与外部事实，防止恢复旧DB后再次认领已发生的部署。恢复后先将未收敛执行标为待核对，比较Jenkins与集群实际状态，再人工解除冻结；不简单把所有Run改READY。

每季度在隔离环境恢复CMDB/Pipeline、对象日志和Jenkins，验证凭据引用、历史读取和一次新交付。权限、安全恢复密钥与演练记录随运行手册维护。

**验收：** 备份确能恢复而非只有文件存在；恢复不会重复部署；跨服务引用与审计一致；RPO/RTO有实测记录。

## OPS-07 联调与完整验收

先用模拟执行器按相同真实接口提供提交接受但响应丢失、迟到claim、重复build、输出缺失、无法取消、日志断线等场景；模拟服务是测试工具，不是产品运行时的第二个兼容执行器。

真实联调准备一个测试空间、测试Git应用、镜像仓库、普通与protected测试环境、既有Deployment和隔离凭据。完成“检查并行 → 构建推送 → 手动部署 → 查看镜像与历史”，再验证失败、取消、超时、API/Worker/Jenkins重启和凭据撤销。

业务验收同时检查用户看到的页面和数据库/远端实际状态，不能只看HTTP200。权限测试至少覆盖五个空间角色、独立平台管理员和跨空间攻击；日志使用含中文、超长行和测试密钥的受控样本验证。完整矩阵与阶段准入见 [实施与验收](12-delivery-and-acceptance.md)。

**验收：** 真实交付链闭环且关键故障场景通过，才能把需求状态标为“待用户验收”；设计文档完成不等同于实现验收。
