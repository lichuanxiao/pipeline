# CMDB 功能与交互方案

覆盖 CMDB-01 至 CMDB-08。CMDB 管理交付所需信息，首期不扩展成主机、网络和机房资产平台。页面以空间、子系统、应用为主线，登记信息后能够直接进入流水线配置与运行。

## CMDB-01 空间成员与权限

**用户任务：** 管理团队的应用、交付权限和访问范围。

平台管理员创建/停用账号和空间，指定首位所有者。空间有不可变 key、名称、说明、状态和成员；名称可改，key 只用于稳定定位。成员从已有启用账号中选择，不通过邮箱发邀请。空间角色每人一个，平台管理员是独立系统身份，跨空间应急访问必须填写原因并审计。

| 空间角色 | 推荐权限 |
|---|---|
| 所有者 Owner | 管理员能力，加转移所有权、归档空间；始终至少一名 |
| 管理员 Admin | 成员、应用、环境、凭据引用、流水线全部操作与受保护环境执行 |
| 发布操作员 Operator | 开发者能力，加受保护环境运行、手动触发与取消 |
| 开发者 Developer | 编辑/发布流水线、运行与取消普通环境任务、查看数据 |
| 观察者 Viewer | 查看配置、运行、脱敏日志和历史；不能获取密钥或修改 |

空间“成员与权限”页展示角色说明、最近变更者和操作记录。移除成员立即影响其下一次操作；已启动脚本不因此自动终止，可由有权成员取消。会话与 SSE 周期复核，前端按钮隐藏不构成权限校验。不能删除/降级最后一个所有者；账号停用前先转移其唯一所有权。

空间归档阻止新 Run 和编辑，允许查看历史与取消活动执行；归档前显示活动 Run 数和“先取消/等待完成”的明确入口，全部收敛后完成归档。不对普通用户暴露跨空间资源是否存在。

空间归档采用ACTIVE→FROZEN→ARCHIVED：先冻结新运行与编辑，已有运行仍可按当前权限放行/取消并收敛，确认无非终态Run后归档。冻结可恢复ACTIVE，归档恢复后先处于FROZEN，管理员核对配置再开放。Pipeline创建与最终执行准入都核对状态，跨服务检查后发生的极短竞态只能留下被拒绝执行的记录，不能绕过ARCHIVED准入。

**验收：** 同一成员在两个空间可有不同角色；替换 spaceId 或 applicationId 无法越权；最后一名所有者不能被移除；权限撤销后的新手动操作返回403。

## CMDB-02 子系统管理

子系统字段：id、spaceId、key、name、description、ownerUserId、status、version。key 在空间内唯一且不可变，名称1–100字符、说明最多2,000字符；负责人必须是当前空间成员。子系统用于归类，无独立成员权限层。

列表显示名称、负责人、应用数量；支持搜索、状态和负责人筛选。新建使用短表单，保存后进入详情并提供“添加应用”。编辑支持 ETag；移除负责人时提示重新指定，不默默改成当前操作者。

应用可在同一空间的子系统间移动，管理员确认后变更，不改变 applicationId、流水线和历史。首期不跨空间迁移。已有应用的子系统先迁移应用才能归档；曾使用的子系统保留记录。完全未被引用的空子系统可删除，二次确认展示名称。

**验收：** 重复 key 提示具体字段；移动应用后原流水线仍属于同一应用；有应用时不能直接删除。

## CMDB-03 应用管理

应用是长期身份，不为每个版本或环境重复创建。字段：id、spaceId、subsystemId、key、name、description、ownerUserId、maintainerUserIds、language、repository、status、version。key 空间内唯一、不可变，负责人必填，技术栈作为可搜索标签，不影响引擎逻辑。

新建分两步：“基本信息”必填名称、标识、子系统、负责人；“交付配置”可稍后补。创建后状态为 ACTIVE，但 `deliveryReadiness` 按环境显示缺失项，不能用一个“可用”标签掩盖不能执行。应用页包含概览、交付配置、流水线、执行历史、镜像与部署、变更记录。

交付配置保存不要求连通外部系统；“验证配置”单独检查 Git、registry、目标访问。验证结果带检查时间和配置版本，修改相关字段后标记需重验。平台验证的可达性不是未来运行保证。

管理员修改身份元数据与交付设置；开发者可读取并组装流水线。转负责人、归档和修改部署目标显示影响摘要。归档阻止新 Run，历史可读；活动 Run 在原快照上收敛，空间/目标硬停用仍按执行准入规则阻止尚未开始的任务。

**验收：** 基本信息未填交付配置也能保存；运行时指出当前环境缺少的字段；重命名应用不会改变历史归属；不能跨空间移动。

## CMDB-04 环境与部署目标

空间统一定义环境：key、name、description、protected、enabled、order。默认建议 dev、test、prod，prod 标记受保护。环境名称不是权限判断依据，依据 protected。只有管理员可取消保护，变更单独确认并审计。

应用每个环境配置一个目标：clusterId、namespace、workloadKind=Deployment、workloadName、containerName、deployCredentialRef。集群连接由平台管理员登记，空间管理员只能选授权给本空间的集群与凭据。镜像拉取凭据和 Deployment 的初始资源由集群维护者预先配置，平台首期更新镜像并等待 rollout。

集群登记使用稳定clusterIdentity，不能把同一集群换URL登记成两个不同身份绕过互斥。同一clusterIdentity+Namespace+Deployment只归属一个应用环境，即使容器不同也不能被另一应用环境重复登记；数据库保留目标身份归属记录。修改当前目标新增目标配置，旧目标身份与历史归属保留，已有Run仍使用其快照且不允许其他应用接管旧目标；回收/转移属于单独受控迁移。

表单先选环境与集群，再选择/输入 Namespace、Deployment、容器；有查询权限时提供候选，没有权限时允许明确输入并验证。不得因为无法拉取选项删除用户已填值。验证只读，区分“连接失败”“目标不存在”“无更新权限”；不把 kubeconfig 内容显示给浏览器。

环境禁用阻止新 Run 和尚未提交的任务，不中断已运行任务；页面提供取消入口。一个 Stage 最多一个部署 Job，首期一 Run 一目标，不做多集群并行扇出。

**验收：** 开发者不能执行 protected 环境；同名 Namespace 在不同集群能明确区分；运行页显示快照目标而非最新配置。

## CMDB-05 源码与构建元数据

首期每个应用一个主仓库，HTTPS URL、defaultRef、sourceCredentialRef；不在 URL 中放密码。额外仓库、子模块凭据、多仓库构建首期明确不支持，校验时拒绝而非缺省漏取。仓库主机必须在平台允许列表，后端/Runner 禁止访问元数据服务、loopback 等未授权地址。

镜像配置：registryId、repository、registryCredentialRef；构建默认值：dockerfile、buildContext、testScriptPath，均为仓库内相对路径。模板可允许覆盖非敏感构建路径，镜像仓库、集群和凭据不可通过运行参数覆盖。应用环境可引用空间共享的已登记连接，凭据用途严格区分 source、registry、deploy。

交付配置页将“代码来源”“镜像”“部署目标”分组，先展示常用字段，工具版本由节点池管理。用户可测试源码读取、镜像仓库认证、目标只读访问；失败保留输入并展示可操作原因。外部连接正常也不证明部署一定成功。

需要Git/registry/K8s访问的验证委托Pipeline的受控只读诊断执行，CMDB保存被检配置版本和检查结果；不把执行密钥再复制到CMDB后端。配置变化后旧验证标记过期，检查请求只接受已授权资源ID，不接受任意代理URL。

**验收：** 密钥不进入普通配置响应；路径目录穿越、绝对路径及运行时逃逸工作目录的符号链接被拒绝；镜像仓库不能通过输入注入替换。

## CMDB-06 发布计划与应用版本

Release 使用“发布计划”作为界面名称，避免与发布流水线修订混淆。字段：key、name、description、owner、targetEnvironmentId、plannedAt、status、version；一份计划一个目标环境，包含多个应用项。应用项保存 applicationId、plannedCommitSha、sourceRefLabel、note；commit 必填，分支仅作说明，不决定实际运行版本。

Operator、Admin、Owner可创建、修改草稿和执行计划生命周期动作；Developer和Viewer只读，受保护环境的运行仍按相应执行权限校验。负责人是协调信息，不绕过角色授权。

创建页选择应用后，为每个应用粘贴完整 commit，或从该应用已有构建/运行选择已解析 commit；未验证的 SHA 会在执行准备阶段验证。首期不为发布计划单独建设 Git 浏览器或远端解析任务。这样版本是确定的，不随分支移动而变化。

生命周期 DRAFT → READY → CLOSED，DRAFT/READY 可 CANCELED。DRAFT 可改计划；进入 READY 前所有应用与 commit 完整，之后条目和目标不可变，需变更时复制新计划。READY 的每个应用可独立启动/关联 Run，创建请求必须使用计划 commit，重复点击受幂等保护。关闭要求用户确认，允许记录失败原因关闭；关闭不是“交付成功”的同义词。

计划页逐行显示：计划 commit、最近关联 Run、实际部署镜像/时间、交付结论与“运行”。交付达成要求同应用、目标环境、计划 commit 的关联 Run 成功且有该 Run 成功部署记录；只有测试成功不算。部署已成功但后续检查失败显示“已部署，流水线失败”。历史达成与当前环境是否已被其他运行更新分开显示。

取消计划阻止新关联运行，不自动取消已创建 Run；对话框展示活动 Run 和逐项取消入口。首期不提供“一键按依赖发布所有应用”。

**验收：** READY 计划不能静默改 commit；错误应用或环境的 Run 无法关联；测试成功不计为部署成功；后续部署不抹去计划的历史交付事实。

## CMDB-07 交付上下文接口

Pipeline使用内部服务身份请求同空间应用与环境的完整delivery-context。一次响应包含contextVersion、生成时间、空间/应用/环境状态、源码、镜像、目标、凭据引用及protected标记；多个字段来自CMDB一致读取，不用多次请求拼混合版本。Controller/Folder/节点池映射由Pipeline本地配置补入运行快照，不反向成为CMDB维护的执行配置。

contextVersion 随相关交付配置变更递增；凭据明文不返回。创建 Run 时在数据库事务外读取并持久化快照。首期不缓存可用于新执行的授权与交付上下文；普通列表名称可以短缓存并标记更新时间。CMDB 不可用时创建失败503，不生成半份 Run。

执行前准入接口只核对当前空间、应用环境、目标和凭据是否仍允许执行，不替换 Run 快照。目标被硬禁用、凭据撤销、模板封禁时不再启动；重命名、普通配置调整不会改变旧 Run。服务身份仅能按授权空间和用途访问，不能冒充浏览器用户修改成员。

软归档应用与FROZEN空间仅阻止新Run，允许已接受运行继续；ARCHIVED空间、硬禁用目标/环境阻止后续开始。运行准入记录当时保护级别授权，环境后来从普通变为protected时，未获对应级别授权的任务返回PROTECTION_CHANGED，要求有权用户创建新Run，不能沿普通环境授权自动升级。

**验收：** 创建期间 CMDB 变更不会得到混合字段；上下文不可用不创建 Run；当前目标停用后尚未启动的部署被阻止，并显示明确原因。

## CMDB-08 变更、引用与历史保护

所有编辑带 ETag 和审计，配置更新显示字段差异并脱敏。凭据引用不展示原值，负责人/环境/目标变更记录旧新显示值和资源 ID。快照保留历史标签，不能用最新名称冒充当时配置。

常规移除采用归档，已使用应用、环境、集群引用、Release 和凭据元数据不能物理删除。未使用资源的永久删除先检查本地引用并关闭新引用资格，涉及 Pipeline 时再核对引用；远端不可用时拒绝永久删除，仍允许可恢复归档。归档不删除运行历史。

跨服务不承诺瞬时全局锁。创建 Run 与执行认领都核对 CMDB 准入，归档过程中已经获准的远端执行按既有 Run 收敛；需要立即阻止执行时使用硬停用与取消，已开始的脚本仍需核实停止结果。跨空间迁移首期禁止，复制时必须新建身份并重新绑定交付资源。

**验收：** 有历史引用不能永久删除；归档后历史可定位；并发归档与运行不会绕过最后一次执行准入；不会为保护历史继续维护旧配置解释器。
