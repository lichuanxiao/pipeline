# 推荐方案重点取舍

用户已授权先按推荐方案写全，再集中修改。本表列出最值得审阅的产品选择，当前方案已经选择右侧推荐值，不再把每项留成未回答问题。修改时同步更新对应章节、数据、接口、示例与验收。

| 编号 | 推荐选择 | 理由与用户影响 | 对应需求 |
|---|---|---|---|
| DEC-01 | 轻量业务文件、普通结构体与函数、按需接口 | 代码容易找到和修改，不为模式制造多层转发 | ARCH-01/02/03 |
| DEC-02 | API与Worker分进程，同仓库共用逻辑，MySQL待办队列 | API快速返回，执行可恢复；首期不增加消息中间件 | ARCH-05、RUN-08 |
| DEC-03 | 五个空间角色，生产类动作由Operator/Admin/Owner执行 | 常规开发与受保护环境区分，首期不做自由权限编辑器 | CMDB-01、PIPE-06 |
| DEC-04 | 平台管理员发布能力脚本，业务用户组装参数 | 降低执行器暴露面；普通用户不能写Groovy | JOB-01/03/06 |
| DEC-05 | 一应用一主仓库、HTTPS，一个环境一个Deployment目标 | 首次交付链清楚；多仓库、多目标和初始资源创建后续增加 | CMDB-04/05 |
| DEC-06 | 一个共享草稿、不可变修订、只运行修订 | 保存未完成工作安全；发布与执行互相独立 | CFG-01/06/08 |
| DEC-07 | 纵向Stage、同组Job并行，无任意DAG | 顺序容易读，减少画布和依赖编辑复杂度 | CFG-02/04、WEB-03 |
| DEC-08 | 手动Job只等待自身，不能现场改参数 | 兄弟自动任务可继续；放行一个不会批量部署其他任务 | RUN-03 |
| DEC-09 | 同应用环境所有Pipeline共享一个活动Run槽，等待人工占槽 | 保持交付顺序，代价是等待人工会阻塞后续构建；界面明确显示阻塞 | RUN-04 |
| DEC-10 | 人工等待24小时、应用槽排队24小时、Jenkins排队30分钟 | 避免无限占槽，空间管理员可按团队节奏调整人工时限 | RUN-07 |
| DEC-11 | 首次失败停止新工作，已认领兄弟继续收敛 | 保存并行任务结果，不因兄弟失败突然杀掉已进行副作用 | RUN-05 |
| DEC-12 | 取消先记录停止意图，确认远端结束后才释放槽 | 失联时等待更久，但不会让旧部署与新部署并发 | RUN-06/08 |
| DEC-13 | 首期整体新Run，无单Job重试/失败点恢复/自动脚本重试 | 避免复用旧产物和重复副作用；可用部署专用流水线修复 | RUN-09 |
| DEC-14 | Run创建固定配置，PREPARING解析分支并固定commit | 排队时可能获取较新分支；要求排队前固定时使用SHA | RUN-01、DATA-01 |
| DEC-15 | 发布计划每应用明确commit，READY后冻结 | 发布版本确定；用户从已有运行选择SHA或手动粘贴，首期无独立Git浏览器 | CMDB-06 |
| DEC-16 | 部署只接受可追溯同应用镜像digest | 结果可重现，任意外部镜像暂不能直接部署 | JOB-08、DATA-04 |
| DEC-17 | 每空间一个Controller映射和Folder Runner，构建/部署Agent隔离 | 简单映射与空间隔离；故障不自动跨Controller迁移 | JENKINS-01/02/03/04 |
| DEC-18 | 独立workspace，不跨Job传本地文件，缓存可丢 | 并行安全、重启可恢复；通过镜像/制品仓库共享结果 | JENKINS-05 |
| DEC-19 | 平台持久归档日志，对象存储作为必要依赖 | 日志不依赖用户打开页面或Jenkins记录一直存在 | DATA-06、OPS-03 |
| DEC-20 | 日志30天、结构化历史730天、引用可延长 | 清理规则可预测；成本与审计需求可调整，registry不自动清理 | DATA-08 |
| DEC-21 | 本地账号、服务端会话、同源网关、每请求当前授权 | 权限撤销清楚；CMDB授权故障会影响新操作 | OPS-01 |
| DEC-22 | Release汇总单应用独立运行，站内待办，无跨应用调度 | 先完成真实交付闭环；SSO/Webhook/定时/外部通知/审批后续增加 | CMDB-06、WEB-01 |
| DEC-23 | 20Stage/20Job每Stage/100Job总计，初始100活动Run | 控制编辑和调度规模；容量为待压测目标，可配置配额 | CFG-02、RUN-04、DATA-09 |
| DEC-24 | 破坏性升级排空执行并协同更新，只运行当前协议 | 满足不写兼容代码的硬约束；需要安排升级窗口 | ARCH-08、OPS-05/06 |

## 建议先看哪几项

优先审阅DEC-03权限、DEC-05交付范围、DEC-09等待占槽、DEC-10超时、DEC-13重试方式、DEC-15发布计划commit、DEC-20历史保留。这些最直接影响团队使用习惯和运维成本。

已有用户明确选择如技术栈、API/Worker分进程、Stage串行/Job并行、单Job手动和不写兼容代码，仍按原选择执行；本文不会因其他项目采用不同做法而自动替换它们。
