# 流水线资源管理

覆盖 PIPE-01 至 PIPE-06。流水线管理维护资源身份、应用归属、启停和归档；具体 Stage/Job 编辑由同一 definition 模块承担，见 [组装方案](05-pipeline-editor.md)，不另造一套配置资源身份。

## PIPE-01 应用与流水线关系

一个应用可有多条流水线，如“检查与构建”“测试环境交付”“部署指定镜像”。一条 Pipeline 只属于一个应用，归属创建后不可直接修改；跨应用使用复制并重配上下文。字段包括 id、spaceId、applicationId、key、name、description、enabled、archivedAt、allowedEnvironmentIds、defaultRevisionId、version。

key 应用内唯一且不可变，名称1–100字符。可运行环境来自当前应用启用环境，配置可限定其子集；选择多个环境不是同一 Run 部署多个环境。默认流水线按应用设置一个可选指针，只用于入口推荐，不触发自动执行；默认项必须启用且有发布修订。

应用“流水线”页显示用途、环境范围、已发布修订与最近运行。创建向导默认允许非生产环境，加入 protected 环境要明确展示保护标签，由管理员维护范围。具体执行权限在每次 Run 和手动操作时再次判断。

**验收：** 一个应用可建多条流水线；环境筛选不允许运行未授权目标；修改名称不影响修订和历史。

## PIPE-02 列表与查询

空间流水线列表支持应用/子系统、名称、状态、环境、创建人筛选，默认20条并保留 URL 查询条件。列为名称与应用、启用状态、草稿提示、最新发布、最近 Run 状态/时间、操作；不把所有 Job 和日志塞进列表。

最近执行在批量查询中获取，不逐条调用服务。用户可从应用内列表查看该应用，或在空间列表定位问题。空列表提供“新建流水线”；无创建权限显示用途说明。没有运行记录显示“尚未运行”，不能当作成功。

最近 Run 仍显示其实际环境，用户选择环境筛选时最近运行也按该环境计算；待手动操作计数是当前有权操作的 Job 数，不是失败数。列表摘要与详情允许短暂最终一致，进入详情或操作时获取当前状态。

**验收：** 切页和刷新保留筛选；不存在“最近成功”覆盖“最近运行失败”的误导；不可见应用的流水线不计入列表和总数。

## PIPE-03 创建与复制

新建流程：选应用 → 填名称/key/用途 → 选“空白”或“质量检查+构建+手动部署”示例 → 进入草稿。示例只引用用户可见的当前模板版本；能力未准备时给出缺失清单，允许保存空白草稿，不生成假节点。

创建事务同时写 Pipeline、唯一草稿与审计，返回201并跳编辑器。首次没有发布修订时“运行”不可用，说明“请先发布配置”。

新身份由服务端默认enabled=true，无修订时仍不可运行；开发者完成发布后可运行普通环境，避免每次建流水线都要管理员启用。复制的新身份同样没有发布修订，不复制默认项；后续显式启停仍由管理员控制。

复制可以从指定已发布修订或当前草稿创建新 Pipeline，默认名称“原名称 副本”，key 必须唯一。源与目标都需查看/创建权限；首期同空间复制，可跨应用。复制后不自动发布或启用默认指针，不复制运行历史、凭据实际值、Release 关联和外部执行状态。

复制向导列出应用/环境/凭据/CMDB 引用需重新绑定的项目；模板版本与普通参数可保留，目标应用不支持的字段显示待修复。创建与复制使用幂等键，重复提交不产生多个资源。

**验收：** 空白创建可保存；跨应用复制不会继续部署源应用；复制后用户必须校验发布才可运行。

## PIPE-04 启用与停用

停用阻止创建新 Run，包括普通启动、Release 启动和重新运行；已接受的 QUEUED、PREPARING、执行中和手动等待 Run 继续按原规则处理。停用不等于取消，确认框展示活动 Run 数并提供“查看活动运行”。不能隐式取消已在执行的部署。

停用的流水线仍可编辑、发布和查看历史；启用时校验应用未归档、至少一个有效修订、允许环境存在。已封禁模板或缺失目标会显示“配置需修复”，启用不跳过运行准入校验。

角色 Admin/Owner 可启停，Developer/Operator 可编辑发布。列表行菜单中的停用使用明确文案“阻止新的运行”，执行中状态单独显示。

**验收：** 停用后新 Run 返回 PIPELINE_DISABLED；先前排队 Run 不被无提示取消；启用不重启历史 Run。

## PIPE-05 归档、删除与恢复

归档需要停用且不存在非终态 Run；有活动项时展示链接，引导等待或取消。归档保留修订、日志引用、镜像和部署记录，默认列表隐藏，可在“已归档”筛选中查看和恢复。

恢复只恢复身份与草稿，保持停用，重新校验后由管理员启用；若应用已归档须先恢复应用。历史引用不会因恢复改写。

首期用户界面不提供已使用流水线的永久删除。完全未发布、未运行、没有历史引用的空资源可删除，确认展示名称，事务内再次检查条件。Release 的历史关联保留，归档不能让已有计划伪装缺失。

**验收：** 活动 Run 阻止归档；归档后历史仍可从 Run 深链接进入；恢复不会自动运行；删除检查与提交之间的并发变化能阻止误删。

## PIPE-06 操作权限与审计

| 动作 | Viewer | Developer | Operator | Admin/Owner |
|---|---|---|---|---|
| 查看配置、修订、历史与脱敏日志 | 是 | 是 | 是 | 是 |
| 创建、复制、保存草稿、发布修订 | 否 | 是 | 是 | 是 |
| 普通环境新 Run、手动触发、取消 | 否 | 是 | 是 | 是 |
| protected 环境执行与取消 | 否 | 否 | 是 | 是 |
| 启停、环境范围、默认项、归档与恢复 | 否 | 否 | 否 | 是 |
| 市场脚本发布、Jenkins 全局配置 | 否 | 否 | 否 | 需独立平台管理员身份 |

取消不是只能由创建者操作：有对应环境权限的成员可取消，以免人员离开导致任务无法收敛。生产类动作要求填写操作原因；“手动执行”是操作授权，不提供审批人分离或多人会签的承诺。

记录创建、元数据修改、复制、启停、草稿保存/冲突、发布、归档、运行、手动放行和取消。审计包含 actor、space、对象、时间、requestId、原因和脱敏差异；自动保存相邻同用户草稿变化可合并展示，持久化版本仍递增。页面返回 availableActions 便于展示，后端始终复核。

**验收：** 伪造按钮请求不能越权；protected 标签变化后按当前保护级别授权；所有副作用能追溯操作者和请求。
