# 单项需求记录模板

每项需求写清问题、行为和结论即可。简单需求可以只有几段，不要求填满固定栏目，也不为每个函数、接口或目录分别建立需求。

## 基本信息

需求 ID、名称、当前状态、必要的前置需求。

## 问题与场景

谁在什么情况下需要完成什么操作，怎样算成功。

## 需要讨论的选择

只列会真实改变行为或实现成本的问题，说明建议和取舍。常规命名、格式等按代码规范处理，不反复发选择题。

## 结论

区分已确认结论与建议。确认后正文只保留当前方案，变化原因留简短记录。

## 必要细节与验收

按本需求实际需要写字段、接口、权限、异常、并发、迁移和验收场景，不涉及的内容直接省略。实现任务引用需求 ID，验证关键行为。
