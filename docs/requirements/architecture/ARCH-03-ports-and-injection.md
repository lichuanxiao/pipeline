# ARCH-03 按需使用接口与代码复用

状态：现行推荐基线见 [工程规范 ARCH-03](../../design/01-engineering.md#arch-03-接口与复用)。本文件保留按需抽象的解释；目标是容易理解和修改，不追求接口数量、模式完整性或层次齐全。

## 普通代码优先

只有一个明确实现时，先使用普通函数和具体结构体。模块之间可以调用清楚的 Service 方法，不要求 public 包、跨模块适配器和多轮数据转换。

Jenkins 和 CMDB 的调用分别集中在 client 中，负责请求、认证、超时和响应解析；业务流程仍放在相应模块的 Service。这样能集中外部调用代码，又不需要搭建通用执行器框架。

## 什么时候需要接口

出现真实需要再添加接口，例如业务测试需要控制 Jenkins 的返回结果，或者确实需要替换某个依赖。接口只包含实际调用的方法，放在使用它的地方。

不强制每个 Repository、Service 都有接口，也不强制把提交、观测、取消、日志分别建成四个接口。按实际调用与测试需要决定粒度。

不预建执行器注册中心、插件系统、通用 Repository 或为了“以后可以替换”而增加无实际用途的包装。

## 依赖如何创建

在 API、Worker 的启动入口，直接调用构造函数创建数据库连接、Client 和 Service，再注册路由或启动后台循环。

依赖多到影响阅读时，提取普通初始化函数即可；不强制建立 bootstrap 包，不引入 DI 框架或 service locator。两个入口复用相同业务实现，不通过全局变量保存当前用户或运行状态。

## 复用的边界

- 相同业务规则应复用，避免多处修改容易遗漏。
- 只是代码长得像、业务含义不同的逻辑，不急着合并成通用组件。
- 数据结构含义一致时可以复用；存在暴露字段、验证或语义差异时再拆分。
- 遇到重复的纯转发层，优先删掉；遇到难懂的长流程，按真实职责拆开。
- 所有改动遵守 ENG-001，只保留当前方案，不为旧调用保留接口包装。

## 事务和测试

事务按 [ARCH-02](ARCH-02-persistence.md) 的直接写法处理，不通过接口隐藏数据库事务。测试覆盖真实行为，需要模拟外部依赖时再提取接口，不为现有抽象反过来制造测试需求。

## 当前结论

保留手工创建依赖和实际业务复用，撤回强制公开契约、最小端口拆分和跨模块桥接。接下来从具体功能判断是否需要接口，不继续为尚未实现的代码设计抽象体系。
